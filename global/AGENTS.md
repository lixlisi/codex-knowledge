# 全局开发规范

- 新增或修改代码时，对复杂业务逻辑、边界条件和不易理解的设计取舍添加简洁、清楚的中文注释。
- 避免为显而易见的代码添加重复、无意义的注释。
- 修改或提交代码前，先检查并遵循当前项目已有的规范，包括但不限于：
  - 仓库内的 AGENTS.md
  - CONTRIBUTING.md
  - README.md
  - commitlint、Commitizen 等配置
  - 最近的 Git 提交记录
- Git 提交信息的格式、语言、类型和 scope 以项目现有约定为准。
- 如果项目规范与本文件冲突，以项目内更具体的规范为准。
- 只有用户明确要求时才创建 Git commit。
- 执行 Git commit 前，先获取远端最新代码，并按项目约定将当前分支与对应远端分支同步；处理完冲突、完成必要验证后再提交。同步时保留本地未提交改动，不得强制覆盖；若远端不可用或无法确定对应分支，应说明原因，不得跳过同步直接提交。
