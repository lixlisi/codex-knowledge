# 跨机器使用个人经验库

## 主力机器更新

1. 把跨项目有效、已经验证的结论写入 `notes/`；把可反复执行的步骤写入 `playbooks/`。
2. 把只属于某个项目的规则放在该项目的 `AGENTS.md`，避免把项目路径和临时进度写进全局规则。
3. 提交前检查差异，确认不含密钥、个人数据或本机认证文件。
4. 根据用户授权和仓库规范提交、推送。

## 其他机器接手

1. 拉取知识仓库最新内容。
2. 对比并合并 `global/AGENTS.md` 与当前机器的全局规则。
3. 拉取目标项目代码，并检查项目中的 `AGENTS.md`、README 和构建说明。
4. 如需接续具体任务，阅读项目内的交接记录，并核对分支、工作区状态与测试结果。
5. 在新任务中要求 Codex 复述当前适用的规则和下一步，确认其读取了正确文件。

## 经验分类

| 内容 | 建议位置 |
| --- | --- |
| 每个项目都适用的行为规则 | `global/AGENTS.md` |
| 某个项目的构建、测试、提交约定 | 项目仓库的 `AGENTS.md` 或 README |
| 可反复执行的排障、审查流程 | `playbooks/` |
| 可复用但需要事实依据的经验 | `notes/` |
| 当前任务的进度和未完成事项 | 项目内 `HANDOFF.md`、Issue 或 PR |
